# Development

Everything runs in Docker; no local Python is needed.

```bash
docker compose -f docker-compose.dev.yml build dev
docker compose -f docker-compose.dev.yml run --rm dev pytest          # tests
docker compose -f docker-compose.dev.yml run --rm dev ruff check .    # lint
docker compose -f docker-compose.dev.yml run --rm dev ruff format .   # format
docker compose -f docker-compose.dev.yml up app                       # run audium on :8080
```

The `dev` image contains the dependencies; the source in `backend/` is mounted, so code changes need no rebuild. The `app` service creates the admin `admin` / `admin-dev-password` (development only).

## Layout

```
backend/audium/
  api/         HTTP routers (FastAPI). No business logic; they call services.
  services/    business logic and permission checks (users, auth, roots, library)
  db/          schema (SQLAlchemy Core), engine, migrations, pagination, search (FTS5), dialect helpers
  scanner/     walking, tag reading (mutagen), covers, incremental scan, scan jobs
  jobs/        DB job queue and worker loop
  devtools/    test library generator, load test, audio fixtures
  supervisor.py  runs API + workers in one container
```

## Database migrations

Schema lives in `audium/db/schema.py`. After changing it, generate a migration in the container and review it:

```bash
docker compose -f docker-compose.dev.yml run --rm dev python -c "
from alembic import command; from audium.db.migrate import alembic_config
command.revision(alembic_config('sqlite:////tmp/gen.db'), message='describe change', autogenerate=True, rev_id='0002')"
```

(Upgrade `/tmp/gen.db` to the previous head first if it already exists.) Migrations run automatically at startup; a copy of the SQLite file is saved to `/data/backups` before an upgrade.

## Dependencies

`backend/requirements.lock` (runtime) and `backend/requirements-dev.lock` pin exact versions for reproducible images. To update: install `backend/` into a fresh `python:3.12-slim-bookworm` venv, `pip freeze`, and copy the result.

## Performance testing

```bash
# 100k real audio files (~1-2 GB, takes a while) in a Docker volume
docker volume create audium-testmusic
docker run --rm -v audium-testmusic:/music audium:dev python -m audium gen-testlib --mode files --tracks 100000 --out /music/testlib

# or: 100k rows directly in the database (seconds; no files, nothing to stream)
docker compose -f docker-compose.dev.yml run --rm dev python -m audium gen-testlib --mode db --tracks 100000

# latency against a running instance
docker exec audium audium loadtest --user admin --password ... --requests 3000 --concurrency 4
```

The load test covers the web API and the Subsonic API (`rest_*` rows: album lists, album details, search, a page of a full library sync, the artist index); for the latter it creates a temporary app password. It fails (exit code 1) if the p95 of either search exceeds 200 ms or more than 1 % of requests fail.

## Frontend

Svelte 5 + Vite + TypeScript in `frontend/`. The production build is served by the backend from `AUDIUM_WEB_DIR` (in the image: `/opt/audium/web`).

```bash
cd frontend
npm ci
npm run dev      # http://localhost:5173, proxies /api to http://127.0.0.1:8080 (AUDIUM_DEV_BACKEND)
npm run check    # svelte-check (types)
npm test         # vitest: queue, format selection, error translation
npm run build    # -> frontend/dist
```

Layout: `src/lib/` holds the API client, router, player and pure logic (`queue.ts`, `playback.ts`, unit-tested); `src/lib/components/` the building blocks (`VirtualList`, `VirtualGrid`, `PlayerBar`, ...); `src/routes/` the pages.

The PWA icons in `frontend/public/` are generated by `frontend/scripts/make_icons.py` (Pillow; run it in the dev container). The service worker (`frontend/public/sw.js`) is only registered in production builds.

## CI

`.github/workflows/ci.yml` runs on every push and pull request:

- **backend:** builds the `dev` image stage and runs `ruff check`, `ruff format --check` and `pytest` in it;
- **frontend:** `npm run check`, `npm test`, `npm run build`;
- **image:** builds the runtime image for `linux/amd64` and `linux/arm64`. Only for version tags (`v0.1.0`) it is pushed to `ghcr.io/mushroom-media/audium` (tags `0.1.0`, `0.1` and `latest`).

## Releasing

1. Update the version in `backend/pyproject.toml`, `backend/audium/__init__.py` (shown by `/api/health` and the Subsonic API) and `frontend/package.json` (plus `npm install --package-lock-only`), and move the `Unreleased` entries in `CHANGELOG.md` to a new section.
2. Commit, then tag and push: `git tag -a v0.1.0 -m "audium 0.1.0" && git push origin main v0.1.0`.
3. CI tests, builds and pushes the image. Create a GitHub release for the tag with the changelog section as text.
4. Only for the very first release: the new package on GHCR is private. Make it public under the repository's *Packages → audium → Package settings → Change visibility*.

`docker-compose.yml` uses the `major.minor` tag (`0.1`), so users get bug-fix releases with `docker compose pull`. For a new minor version, change the tag there too.

To run a build from this checkout instead of the published image, add the override file: `docker compose -f docker-compose.yml -f docker-compose.build.yml up -d --build` (image `audium:local`).

On x86_64 the image contains Essentia with TensorFlow (style detection, fingerprints); `--build-arg AUDIUM_ML=0` builds without it. arm64 never has it.
